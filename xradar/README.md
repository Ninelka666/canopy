# xradar

Ищет посты в X, которые **взлетают прямо сейчас** по твоим темам: например
100k просмотров за первый час. Запускается локально на время работы, сигналы
приходят в Telegram.

Только стандартная библиотека Python 3.9+. Никаких зависимостей, никакого
`pip install`.

## Главное ограничение, вокруг которого всё построено

**В поиске X нет оператора `min_views`.** Есть только `min_faves:`,
`min_retweets:`, `min_replies:`. Запросить «покажи посты со 100k просмотров»
технически невозможно — ни в веб-поиске, ни в API.

Поэтому xradar работает в два шага:

1. **Грубый фильтр по лайкам.** Чтобы поймать пост на 100k просмотров, ищем
   посты за последний час с `min_faves:333` (отношение лайков к просмотрам у X
   обычно 1:200…1:500). Вместо десятков тысяч постов возвращается несколько
   десятков.
2. **Просмотры читаем только у них** и считаем скорость самостоятельно.

Цена этого обхода: **пост с большими просмотрами и малым числом лайков может
проскочить мимо** — так бывает у видео и новостных срочных постов. Понизь
`views_per_like` в конфиге, чтобы расширить сеть (дороже), или задай
`min_faves` для темы вручную.

## Что считается «взлётом»

Три разные вещи, которые важно не путать:

| Метрика | Что означает |
|---|---|
| `views/h` средняя | Просмотры с момента публикации, делённые на возраст. Пост, который сделал 200k за десять минут и умер, через час всё ещё выглядит быстрым. |
| `views/h` текущая | Прирост просмотров между двумя последними снимками. Именно она говорит «всё ещё растёт». Нужен минимум второй проход. |
| `reach ×N` | Просмотры, делённые на число подписчиков автора. Выше ~3 — пост вышел за пределы своей аудитории. Это и отличает вирусный пост от обычного вторника у крупного аккаунта. |

100k просмотров у аккаунта на 2 млн подписчиков — рутина. 100k у аккаунта на
8 тысяч — событие. Правило `escape_velocity` ловит именно второе.

## Быстрый старт (бесплатно, без ключей)

```bash
cd xradar
python3 -m xradar init                    # создаст config.json и .env.example
python3 -m xradar scan --dry-run          # source = mock: синтетика, 0 рублей
```

Источник `mock` генерирует детерминированные посты, которые растут по
логистической кривой — можно проверить всю цепочку, формат сообщений и правила,
не покупая доступ.

## Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather), получи токен.
2. Напиши своему боту любое сообщение.
3. Открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьми оттуда
   `chat.id`.

```bash
export TELEGRAM_BOT_TOKEN=123456:AA...
export TELEGRAM_CHAT_ID=987654321
python3 -m xradar check      # проверит конфиг, ключи и отправит тестовое сообщение
```

Токены берутся из окружения — в `config.json` лежат только имена переменных
(`${TELEGRAM_BOT_TOKEN}`), поэтому файл можно спокойно коммитить.

## Выбор источника данных

| Источник | Цена | Просмотры | Замечания |
|---|---|---|---|
| `mock` | 0 | синтетика | Для проверки и отладки |
| `twitterapi_io` | ~$0.15 / 1000 постов | `viewCount` в ответе поиска | Сторонее зеркало, серая зона по ToS X. Отдаёт и подписчиков автора — одного запроса хватает |
| `x_api_v2` | ~$0.005 за чтение поста (~в 33 раза дороже) | `impression_count`, **часто 0 или занижен** | Официальный. С сентября 2026 тарифов Basic/Pro больше нет, только pay-per-use |

Если просмотры не пришли, xradar **не считает это нулём**: он оценивает
просмотры по лайкам, помечает значение как `~оценка` и показывает
«views estimated from likes». Правило может отказаться срабатывать на оценке —
`"allow_estimated_views": false`.

```bash
export TWITTERAPI_IO_KEY=...
# в config.json: "source": "twitterapi_io"
python3 -m xradar check
```

## Рабочий режим

```bash
python3 -m xradar watch              # опрос каждые 5 минут, Ctrl+C чтобы выйти
python3 -m xradar watch --interval 180 --topic ai-agents
python3 -m xradar top --hours 6      # что уже в базе, по убыванию скорости
python3 -m xradar cost --days 14     # сколько постов скачано и на какую сумму
python3 -m xradar prune --days 14    # почистить старое
```

Один и тот же пост не присылается дважды: повтор только если просмотры выросли
в `renotify_growth_factor` раз (по умолчанию 3).

## Правила

Правило — это набор условий; срабатывает, когда выполнены **все** заданные.
Пост попадает в сигнал, если сработало **хотя бы одно** правило. Условие на
метрику, которую не удалось вычислить, считается невыполненным — инструмент не
объявляет пост взлетающим на данных, которых у него нет.

Три правила из коробки:

```json
{ "name": "flying_1h", "max_age_min": 90, "min_views": 100000, "min_likes": 50 }
```
Буквально то, что ты просил: ~100k просмотров в первый час.

```json
{ "name": "escape_velocity", "max_age_min": 180, "min_vph": 50000,
  "min_reach_multiple": 3.0, "max_followers": 200000, "min_likes": 50 }
```
Небольшой аккаунт, вышедший за пределы своей аудитории. Самый полезный сигнал.

```json
{ "name": "accelerating", "max_age_min": 240, "min_age_min": 10,
  "min_vph_now": 80000, "min_accel": 1.25, "allow_estimated_views": false }
```
Ещё разгоняется между последними снимками — значит есть время отреагировать.

Доступные поля: `max_age_min`, `min_age_min`, `min_views`, `min_vph`,
`min_vph_now`, `min_accel`, `min_reach_multiple`, `min_followers`,
`max_followers`, `min_likes`, `min_engagement_rate`, `min_author_outlier`,
`allow_estimated_views`. Опечатка в имени поля — ошибка при старте, а не
молчаливо проигнорированное условие.

`min_author_outlier` сравнивает текущую скорость с медианной скоростью
**прошлых постов этого автора**: нужно, чтобы в базе накопилось хотя бы 3 его
поста, иначе условие не выполняется.

## Темы

```json
{
  "name": "ai-agents",
  "query": "(\"ai agents\" OR \"agentic\" OR \"llm agents\")",
  "lang": "en",
  "min_faves": 200,
  "exclude_replies": true,
  "rules": ["flying_1h"],
  "enabled": true
}
```

`query` — обычный синтаксис поиска X. `min_faves` переопределяет автоматически
вычисленный гейт. `rules` ограничивает набор правил для темы (по умолчанию —
все).

## Контроль расходов

- `max_fetch_per_run` — потолок постов за один проход на тему.
- `daily_fetch_budget` — суточный потолок; при исчерпании `watch` останавливается,
  а не продолжает тратить.
- `python3 -m xradar cost` — фактическое количество скачанных постов по дням и
  оценка суммы.

## Тесты

```bash
python3 -m unittest discover -s tests -t . -q
```

79 тестов: математика скоростей, правила, накопление истории между проходами,
дедупликация, разбор ответов обоих адаптеров, откат при отказе оператора
`min_likes`, экранирование HTML в Telegram и то, что токен не попадает в текст
ошибки.

## Чего этот инструмент не делает

- Не обходит платный доступ к данным X: нужен ключ источника (кроме `mock`).
- Не публикует, не лайкает и не отвечает — только чтение.
- Не гарантирует полноту: гейт по лайкам по своей природе пропускает
  view-heavy/like-light посты, а поиск X сам по себе неполон.
- Официальный recent search видит только последние 7 дней; для сигнала «час
  жизни» это не ограничение.
